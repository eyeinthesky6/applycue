# ApplyCue CV Tailoring Policy

## Purpose

A CV is truthful marketing, not a verbatim archive and not a classroom exercise. ApplyCue helps the user present real experience clearly for a specific role without silently inventing facts.

## Baseline

Preserve the exact supplied CV before editing. Keep a larger evidence-rich base CV; role CVs can be shorter. A baseline search must be recorded before major base-CV rewrites so the user can see the product's effect.

## Enrichment

With permission, the agent may read selected local projects, GitHub, LinkedIn, websites, Linktree, portfolios, blogs, posts, certificates, case studies, and writing samples. It must present material additions, conflicts, chronology issues, and authorship questions for confirmation before adding them to the base CV.

## Claim signals

- **Sourced:** clearly present in the baseline or approved evidence.
- **Reframed:** same underlying fact expressed with JD language or clearer outcomes.
- **New/unconfirmed:** material fact, measure, ownership, title, date, credential, or capability that needs confirmation.

These labels guide the conversation; they are not automatic moral rejection. Once the user confirms a claim, it may be used. If the user does not confirm it, omit or soften it.

Never invent employer, role, date, degree, credential, metric, legal status, authorization, product ownership, team size, or achievement. Never turn “used a tool/project” into “built or authored it” without confirmation.

## Agent ownership

The external agent reads the full JD and writes the role CV. Text similarity code may report keywords but may not select/reject claims or decide fit. Preserve the user's voice unless they approve a new style.

## Required artifacts

For an application, retain:

- tailored Markdown source;
- tailored HTML source;
- ATS-friendly PDF;
- ATS-friendly DOCX;
- the role report/JD reference.

Before upload, open/parse the selected file and confirm candidate, company/role context, and expected sections. Broken, empty, wrong-role, or missing files are hard blockers.

## User review

Ask once for material new claims and risky changes; do not make the user approve every punctuation edit. Show a concise change summary and unresolved facts. Final application approval covers the named CV/application package only.
