# ApplyCue Product Shape

ApplyCue should feel like:

> I learned your actual story, found credible roles, read the full JDs, prepared the right CVs, applied only with your permission, and tracked what happened.

It should not feel like a generic job board, a giant score report, or a collection of scripts the user must operate.

## Interaction

Chat is the primary control surface. The local browser dashboard is a brief evidence/feedback surface: counts, shortlist, links, filters, and thumbs. Feedback returns to the agent; it does not become a second autonomous brain.

## Core decisions

- Code handles objective mechanics, exact identity, artifacts, receipts, and integrity.
- The agent handles fuzzy fit, full-JD understanding, CV writing, and exceptions.
- The user controls access, material facts, scope changes, and every application/send.
- First value is a small set of genuine applications, not hundreds of scored cards.

## Non-negotiables

- no silent invention;
- no fuzzy automatic rejection;
- no current-employer application;
- no silent scope widening;
- no submit without named approval;
- no blind retry after an uncertain outcome;
- no manual code/file editing as the normal user experience;
- no second orchestrator, tracker, dashboard, or judgment owner.

Post-application interview/offer capability is valuable but follows MVP proof.
